# 33-reference-not-a-reference

A person opens the device sign-in page with the user code in the query, `GET /device?code=ABCD-EFGH`, under `policy.reference-code.json`, whose reference parameters are `ref` and `code` (the lab's list). The code is not a reference: its shape and check character do not hold, so `scope.key.reference` is null and the record validates (the ingest's schema requires the eight-character reference alphabet, and a record shipping the code there would be refused and lost). `url.query` keeps the query as sent. The request is a browser's (`scope.reader: browser`) for a path the surface map does not name: the route is `other`, the origin's page passes through byte-identical although every rule of the policy is live (no reference minted, no page facts, no decision), and the body is not read, so `scope.response.bytes` is null.

Files: `request.json`, `upstream.json`, `policy.json` (a pointer to the reference-parameters variant of the toy policy, derived by `scripts/fixture-policies.mjs`), `facts.json`, `expected.json` (generated by the Node run and reviewed). The oracle runs it: the lab's sensor records the raw code in `refQuery`, which the oracle's projection nulls by shape (the second intended deviation, `packages/core/test/oracle/projection.ts`), and the projection's `not_content` names every path the map's docs patterns do not match, so the lab's sensor passes this page through as the core does.
