# 26-inject-dry-run

The HTML docs page of `01-html-page` under `policy.dryrun.json`, where every rule is `dry_run`: the body goes out byte-identical to `upstream.json`, each matching inject rule records one `would_apply` decision with the live reason (`page matched docs face html`), `scope.page.injected` is empty, and the reference is still minted and recorded, because the reference is the record's, not the rule's (plan J3.1 step 6).

Files: `request.json` (what arrived), `upstream.json` (what the origin answers), `policy.json` (a pointer to the dry-run variant of the toy policy, derived from `policy.json` by `scripts/fixture-policies.mjs`), `facts.json` (what the platform supplies), `expected.json` (the masked canonical response, the forwarded request and the records, generated by the Node run and reviewed line by line: the status and the headers, the forwarded request, every record field, the decisions' modes and outcomes), `oracle.json` (the oracle's sensor has no dry run).
