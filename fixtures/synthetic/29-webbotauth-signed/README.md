# 29-webbotauth-signed

A docs page read signed with Web Bot Auth (RFC 9421: `Signature-Agent`, `Signature-Input`, `Signature`) by a synthetic signer (`https://signer.example`, an Ed25519 key derived from a fixed seed by `scripts/sign-webbotauth.mjs`; no real signer's traffic is used), which the fixture policy lists in `signers`. The sensor verifies the signature itself against the host the agent spoke to (`server.address`, `acme.example`), fetching the listed signer's directory once through `io.forward` with the absolute URL (`directory.json` is what the fixture's world answers) and caching it for an hour. Expected: `scope.signature.valid: true`, `reason: verified`, `authority: acme.example`, `scope.reader: signed` (the reader family `exa` is the agent string's, covered by the classifier test), the directory fetch listed among the forwarded requests before the hop to the origin.

Variants in their own directories: `-expired` (the clock ten minutes later), `-wrong-keyid` (a keyid the directory does not hold: `unknown_key`), `-directory-unreachable` (the fetch fails: `directory_unreachable`, remembered a minute), `-authority-mismatch` (sent to `origin.acme.example` while signed for `acme.example`, the host a proxy in front named in `x-forwarded-host`: `authority_mismatch`, a good signature for a host this sensor does not serve), `-unlisted-signer` (a good signature from `https://unlisted.example`, which the policy does not list: `unlisted_signer`, and no directory fetch although the fixture's world would answer one).

Files: `request.json` and `directory.json` (generated by `scripts/sign-webbotauth.mjs --write`, checked current by `test/node/webbotauth-fixtures.test.ts`), `upstream.json` (the toy page), `policy.json`, `facts.json`, `expected.json` (generated by the Node run and reviewed line by line, the signature's verification outcome included), `oracle.json`.
