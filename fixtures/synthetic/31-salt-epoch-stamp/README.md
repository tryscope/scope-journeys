# 31-salt-epoch-stamp

The docs page of `01-html-page` after a salt rotation (plan J3.9): the adapter hashes with the new salt (`facts.salt`, which the install's environment holds and Scope never sees) and stamps the epoch the policy answer carried (`facts.salt_epoch: 2`, from `x-journeys-salt-epoch`). Expected: the same record as `01-html-page` except `observer.salt_epoch: 2` and a different `scope.client.address_hash` for the same address (the hashes of two epochs never collide by construction, which is why the stitcher never joins across epochs). The oracle runs it with the same salt on both sides. The adapters' rule that a policy answer without the header keeps the last epoch seen (and 1 before any answer) is tested in the adapters' tests.

Files: `request.json`, `upstream.json`, `policy.json`, `facts.json` (with `salt` and `salt_epoch`), `expected.json` (generated by the Node run and reviewed line by line, the salt epoch stamp included).
